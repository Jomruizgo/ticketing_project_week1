Build the frontend status and opportunity action experience for the waitlist feature. In the existing Next.js/React application, an enrolled buyer can check their waitlist status and act on an active opportunity. The application shows four distinct states: (1) active enrollment (waiting — no opportunity yet), (2) active opportunity (ticket reserved temporarily, countdown timer showing remaining minutes), (3) consumed opportunity (advanced to payment), (4) expired opportunity (time ran out, no reservation). When the buyer has an active opportunity, the application displays a prominent "Avanzar al pago" button and a countdown timer showing the remaining validity time. Clicking the button calls POST /api/waitlist/opportunities/{id}/claim with the buyer's email. On success (200), the opportunity becomes "consumed" and the buyer is redirected to the payment flow with the reserved ticket. If the opportunity expired (409), the application shows an expiration message. If the email doesn't match (403), an error is shown. The status view updates in real time via SSE connection to GET /api/waitlist/stream?email={email} — when an opportunity_activated event arrives, the UI transitions from "waiting" to "opportunity active" without page reload. When opportunity_expired arrives, the UI transitions to "expired".
