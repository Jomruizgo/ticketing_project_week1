The in-app notification feature lives in the CRUD Service (crud_service/), hexagonal architecture: Domain, Application, Infrastructure, Api. Use .NET 8. Implement a WaitlistSseHub in Infrastructure/Sse that manages concurrent SSE connections keyed by buyer email. The hub maintains a ConcurrentDictionary of email → list of HttpResponse streams. Create a SseNotificationObserver implementing IOpportunityObserver from Domain/Interfaces. When AssignOpportunityHandler (HU3) calls the observer after activating an opportunity, SseNotificationObserver writes the opportunity_activated event to all active SSE streams for that buyer's email. The WaitlistController exposes GET /api/waitlist/stream?email={email} as an async streaming endpoint: sets Content-Type to text/event-stream, Cache-Control to no-cache, Connection to keep-alive, registers the response stream in WaitlistSseHub, and keeps the connection open until the client disconnects (using HttpContext.RequestAborted cancellation token). When the client disconnects, the stream is removed from the hub. The event format follows SSE spec: "event: opportunity_activated\ndata: {json}\n\n". Also emit opportunity_expired events when a DLX consumer triggers expiration. The observer pattern decouples notification from assignment: AssignOpportunityHandler only knows IOpportunityObserver, not the SSE implementation.
