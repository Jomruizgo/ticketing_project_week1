The waitlist status query lives in the CRUD Service (crud_service/), which follows hexagonal architecture: CrudService.Domain, CrudService.Application, CrudService.Infrastructure, CrudService.Api. Use .NET 8 with EF Core for PostgreSQL. Create a GetWaitlistStatusQuery and GetWaitlistStatusHandler implementing IGetWaitlistStatusUseCase in Application/UseCases. The handler receives eventId and buyerEmail, queries IWaitlistEntryRepository for the active entry, and queries IWaitlistOpportunityRepository for any opportunity linked to that entry. It projects a WaitlistStatusResponse containing: the entry (id, eventId, buyerEmail, status, enrolledAt) and optionally the opportunity (id, ticketId, status, activatedAt, expiresAt, remainingMinutes computed from DateTime.UtcNow). The four visible states are: active enrollment (waiting, no opportunity), active opportunity (ticket reserved, countdown running), consumed opportunity (advanced to payment), expired opportunity (time ran out, no reservation). Define IWaitlistOpportunityRepository port in Domain/Interfaces if not already created. Infrastructure implements the repository with EF Core. The WaitlistController exposes GET /api/waitlist/entries?eventId={id}&email={email} and delegates to the use case port. Return 200 with the projected status or 404 if no entry exists. Follow strict TDD: write failing tests in CrudService.Application.Tests for the handler (active entry without opportunity, active opportunity with remaining time, consumed opportunity, expired opportunity, entry not found returns null).
