The email notification feature lives in the CRUD Service (crud_service/), hexagonal architecture: Domain, Application, Infrastructure, Api. Use .NET 8. Define an IEmailSender port in Domain/Interfaces with a method SendOpportunityNotification(buyerEmail, eventReference, expiresAt). Create an EmailNotificationObserver implementing IOpportunityObserver from Domain/Interfaces. When AssignOpportunityHandler (HU3) calls the observer after activating an opportunity, EmailNotificationObserver invokes IEmailSender and records the delivery attempt. Create a NotificationDelivery entity in Domain with fields: Id, OpportunityId, Channel ("email"), Status ("sent"/"failed"), AttemptedAt, ErrorMessage (nullable). Define INotificationDeliveryRepository port in Domain/Interfaces. Infrastructure implements: (1) SmtpEmailSender (or a provider adapter) implementing IEmailSender — for MVP this can be a stub/log-only implementation, (2) NotificationDeliveryRepository with EF Core mapping to notification_deliveries table (snake_case columns). The observer wraps the send call in a try-catch: on success, records status "sent"; on exception, records status "failed" with error message. Crucially, the observer never throws — email failure is isolated from the opportunity lifecycle. Register EmailNotificationObserver alongside SseNotificationObserver in DI as a composite or list of IOpportunityObserver. Database table notification_deliveries: id, opportunity_id (FK), channel, status, attempted_at, error_message. TDD: unit test EmailNotificationObserver with mocked IEmailSender verifying delivery audit on success and on failure, verifying no exception propagates. Integration test with Testcontainers verifying notification_deliveries records.
