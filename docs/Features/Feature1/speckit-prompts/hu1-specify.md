Build an enrollment feature for a waitlist system within an existing ticketing platform. When an event has no immediately available tickets, a buyer can register their interest by providing their email. The system creates a waitlist entry with status "active". Business rules: a buyer cannot have more than one active enrollment for the same event (uniqueness enforced at both application and database level via partial unique index). The waitlist closes when the event date is reached — no enrollments accepted after that. A buyer whose previous opportunity was consumed or expired can re-enroll as long as the waitlist is still open. The enrollment does not reserve any ticket; it only records the buyer's intent. The buyer is identified solely by email — there is no user authentication system. The API endpoint is POST /api/waitlist/entries accepting { eventId, buyerEmail } and returning 201 with the entry, 409 if duplicate, or 422 if the waitlist is closed.
