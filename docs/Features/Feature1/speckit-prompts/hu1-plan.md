The waitlist enrollment feature lives in the CRUD Service (crud_service/), which follows hexagonal architecture: CrudService.Domain, CrudService.Application, CrudService.Infrastructure, CrudService.Api. Use .NET 8 with EF Core for PostgreSQL. Create a WaitlistEntry entity in Domain with fields: Id, EventId, BuyerEmail, Status (active/inactive), EnrolledAt. Define IWaitlistEntryRepository port in Domain/Interfaces. Create EnrollInWaitlistCommand, EnrollInWaitlistHandler implementing IEnrollInWaitlistUseCase in Application/UseCases. The handler validates: (1) event exists and date not reached, (2) no active entry exists for the same buyer+event. Infrastructure implements the repository with EF Core. The database table waitlist_entries has a partial unique index on (event_id, buyer_email) WHERE status = 'active'. Column names use snake_case (PostgreSQL convention). The controller WaitlistController in Api/Controllers delegates to the use case port. Register all DI in Infrastructure/DependencyInjection.cs. Follow strict TDD: write failing tests first in CrudService.Application.Tests for the handler (happy path, duplicate rejection, closed list, re-enrollment) and in CrudService.Infrastructure.Tests for the repository uniqueness constraint using Testcontainers with proper teardown.
