The opportunity expiration feature lives in the CRUD Service (crud_service/), hexagonal architecture: Domain, Application, Infrastructure, Api. Use .NET 8 with EF Core for PostgreSQL. Create an ExpireOpportunityCommand and ExpireOpportunityHandler implementing IExpireOpportunityUseCase in Application/UseCases. The handler: (1) loads the opportunity by ID from IWaitlistOpportunityRepository, (2) validates it is still in "active" status (idempotency — if already expired, ACK and return), (3) transitions status to "expired" using the State pattern (WaitlistOpportunity.TransitionTo with AllowedTransitions: Active→Expired), (4) records the expiration reason and timestamp, (5) saves the updated opportunity, (6) invokes IAssignOpportunityUseCase from HU3 with the same ticketId and eventId to attempt reassignment — this reuses the existing FIFO logic without duplication, (7) if reassignment finds no eligible buyer, publishes a ticket.released event so the ticket returns to general inventory. Create a WaitlistOpportunityExpiredConsumer in Infrastructure/Messaging that listens to the q.waitlist.opportunity.expired queue (dead-lettered from q.waitlist.opportunity.delay). The consumer deserializes the opportunityId from the message and invokes the use case. ACK on success or business-level idempotency, NACK with requeue:false on technical failure. The DLX topology is defined in scripts/setup-rabbitmq.sh: q.waitlist.opportunity.delay (with x-message-ttl and x-dead-letter-exchange/routing-key) → q.waitlist.opportunity.expired. The TTL is set from WAITLIST_OPPORTUNITY_TTL_MS environment variable (default 900000ms = 15min).
