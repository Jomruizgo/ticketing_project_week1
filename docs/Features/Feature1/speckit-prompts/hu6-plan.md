La feature de expiración de oportunidades vive en el CRUD Service (crud_service/), arquitectura hexagonal: Domain, Application, Infrastructure, Api. Usar .NET 8 con EF Core para PostgreSQL. Crear ExpireOpportunityCommand y ExpireOpportunityHandler implementando IExpireOpportunityUseCase en Application/UseCases. El handler: (1) carga la oportunidad por ID desde IWaitlistOpportunityRepository, (2) valida que siga en estado 'active' (idempotencia: si ya expiró, ACK y retorna), (3) transiciona el estado a 'expired' usando el patrón State (WaitlistOpportunity.TransitionTo con AllowedTransitions: Active→Expired), (4) registra el motivo y la marca de tiempo de expiración, (5) guarda la oportunidad actualizada, (6) notifica a los observers mediante IOpportunityObserver.OnOpportunityExpiredAsync para que SseNotificationObserver emita el evento SSE opportunity_expired al comprador, (7) invoca IAssignOpportunityUseCase de HU3 con el mismo ticketId y eventId para intentar reasignación (reutiliza la lógica FIFO existente sin duplicación), (8) si la reasignación no encuentra comprador elegible, publica el evento ticket.returned_to_inventory (routing key: ticket.returned_to_inventory, exchange: tickets, payload: { ticketId, eventId, returnedAt }) para que ReservationService transite el ticket de released a available; esto evita el riesgo de loop que existiría si se publicara ticket.released y el propio TicketReleasedConsumer lo consumiera. Crear WaitlistOpportunityExpiredConsumer en Infrastructure/Messaging que escucha la cola q.waitlist.opportunity.expired (dead-lettered desde q.waitlist.opportunity.delay). El consumer deserializa el opportunityId del mensaje e invoca el caso de uso. ACK en éxito o idempotencia de negocio, NACK con requeue:false en fallo técnico. La topología DLX está definida en scripts/setup-rabbitmq.sh: q.waitlist.opportunity.delay (con x-message-ttl y x-dead-letter-exchange/routing-key) → q.waitlist.opportunity.expired. El TTL se establece desde la variable de entorno WAITLIST_OPPORTUNITY_TTL_MS (por defecto 900000ms = 15 min).
