Crea los principios para un sistema de venta de entradas con microservicios en .NET 8 llamado TicketRush. El sistema vende entradas para eventos a través de un pipeline asíncrono: un Producer publica en RabbitMQ, los workers procesan reservas y pagos, y un CRUD Service gestiona lecturas/escrituras síncronas y notificaciones SSE. Todos los servicios siguen arquitectura hexagonal con DDD: Domain (entidades, puertos como interfaces), Application (casos de uso como Command+Handler), Infrastructure (adaptadores: EF Core para PostgreSQL, publishers/consumers de RabbitMQ, servicios externos), y Api/Worker como puntos de entrada. La regla de dependencia es estricta: Domain no referencia a nadie, Application solo referencia a Domain, Infrastructure implementa puertos de Domain. Ningún framework filtra hacia la lógica de negocio. El proyecto usa TDD estricto (RED → GREEN → REFACTOR; sin código de producción sin una prueba fallida primero). Los commits siguen la convención: test(red):, feat(green):, refactor:. La estrategia de pruebas respeta la pirámide: pruebas unitarias con mocks/stubs para lógica de dominio y aplicación, pruebas de integración con Testcontainers para PostgreSQL con teardown adecuado mediante IAsyncLifetime, y pruebas de aceptación E2E sobre Docker Compose. CI corre en GitHub Actions como Quality Gate bloqueante: el merge a develop está prohibido si algún check falla. El código debe estar en inglés, la documentación en español. El codebase usa GitFlow con ramas de feature desde develop, PRs a develop en el fork. Los patrones de diseño siguen estrictamente la clasificación GoF. Los principios SOLID son innegociables; cada clase o método nuevo tiene una única razón para cambiar. Estándares de calidad: sin AI smells (sin nombres genéricos como data/result, sin comentarios de sintaxis obvios, sin imports muertos, sin try-catch vacíos), sin duplicación de código, nomenclatura intencional.
