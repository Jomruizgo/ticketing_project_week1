Create principles for a .NET 8 microservices ticketing system called TicketRush. The system sells event tickets through an async pipeline: a Producer publishes to RabbitMQ, workers process reservations and payments, and a CRUD Service handles synchronous reads/writes and SSE notifications. All services follow hexagonal architecture with DDD: Domain (entities, ports as interfaces), Application (use cases as Command+Handler), Infrastructure (adapters: EF Core for PostgreSQL, RabbitMQ publishers/consumers, external services), and Api/Worker as entry points. The dependency rule is strict: Domain references nothing, Application references only Domain, Infrastructure implements ports from Domain. No framework leaks into business logic. The project uses strict TDD (RED → GREEN → REFACTOR, no production code without a failing test first). Commits follow the convention: test(red):, feat(green):, refactor:. Testing strategy respects the testing pyramid: unit tests with mocks/stubs for domain and application logic, integration tests with Testcontainers for PostgreSQL and proper teardown via IAsyncLifetime, and E2E acceptance tests over Docker Compose. CI runs on GitHub Actions as a blocking Quality Gate — merge to develop is forbidden if any check fails. Code must be in English, documentation in Spanish. The codebase uses GitFlow with feature branches from develop, PRs to develop on the fork. Design patterns follow strictly the GoF classification. SOLID principles are non-negotiable; every new class/method has a single reason to change. Code quality standards: no AI smells (no generic variable names like data/result, no obvious syntax comments, no dead imports, no empty try-catch), no code duplication, intentional naming.
