Build an opportunity assignment feature for the waitlist system. When a ticket is released (reservation expired without payment or payment rejected), the system automatically detects the release via a RabbitMQ consumer listening to the ticket.released routing key. It then checks if any buyer has an active enrollment in the waitlist for that event. If eligible buyers exist, the system selects the next one using a FIFO (first-in, first-out) priority strategy based on enrollment time. It reserves the ticket temporarily for that buyer and creates a waitlist opportunity with status "active" and a configurable validity period (default 15 minutes via WAITLIST_OPPORTUNITY_TTL_MS). The buyer's enrollment becomes "inactive" upon opportunity activation. If the temporary reservation fails, no opportunity is created and the enrollment stays active for the next attempt. The failure is logged for diagnostics. If no eligible buyer exists, the ticket returns to general inventory available for direct purchase. Two simultaneous releases for the same event cannot be assigned to the same buyer — enforced by a unique constraint allowing only one active opportunity per enrollment. The system publishes an opportunity_activated event for downstream consumers (notifications).
