La feature de UI de inscripción vive en el directorio frontend/, una aplicación Next.js con React, TypeScript, Tailwind CSS y componentes shadcn/ui. Modificar la página de detalle del evento (app/events/[id]/page.tsx o el componente de detalle del evento relevante) para renderizar condicionalmente un formulario de inscripción en lista de espera cuando el evento no tiene entradas disponibles y la fecha del evento no pasó. Crear el componente WaitlistEnrollForm en components/ que acepta eventId como prop: tiene un campo de entrada de correo electrónico y un botón de envío etiquetado 'Unirse a la lista de espera'. Al enviar, llama al endpoint POST /api/waitlist/entries del CRUD Service mediante una nueva función enrollInWaitlist(eventId, buyerEmail) agregada a lib/api.ts. Manejar respuestas: 201 → mostrar mensaje de éxito y mostrar la inscripción como activa, 409 → mostrar 'Ya tienes una inscripción activa', 422 → mostrar 'La lista de espera ya cerró'. Agregar el tipo WaitlistEntryResponse a lib/types.ts: { id: number, eventId: number, buyerEmail: string, status: string, enrolledAt: string }. Lógica de la página del evento: si availableTickets > 0, mostrar el flujo de compra existente; si availableTickets === 0 y la fecha del evento está en el futuro, mostrar WaitlistEnrollForm; si la fecha del evento pasó, mostrar 'Lista de espera cerrada'. Usar la configuración de URL base de la API existente en lib/api.ts. Seguir los patrones de componentes existentes: Card, Button, Input de shadcn/ui, notificaciones toast para feedback. Sin cambios en backend: esta HU consume la API construida en HU1.
