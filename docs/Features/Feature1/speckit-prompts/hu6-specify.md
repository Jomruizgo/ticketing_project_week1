Build an opportunity expiration feature for the waitlist system. When an active opportunity's validity period (default 15 minutes, configurable via WAITLIST_OPPORTUNITY_TTL_MS) elapses without the buyer claiming it, the system automatically marks the opportunity as expired. The expiration is detected via a Dead Letter Exchange (DLX) mechanism: when the opportunity was created, a message was published to a delay queue with a TTL matching the validity period; when the TTL expires, RabbitMQ routes the message to an expiration queue. Upon processing the expiration: the opportunity status changes to "expired" with the reason and exact timestamp recorded. Then the system checks if another buyer has an active enrollment for the same event. If yes, it reassigns the ticket to the next eligible buyer by reusing the same assignment flow from HU3 (FIFO priority, temporary reservation, opportunity creation). If no eligible buyer exists, the ticket returns to general inventory available for direct purchase. The expired buyer's enrollment stays inactive, but they can re-enroll. The expiration cycle continues until either a buyer claims an opportunity or no more enrollments exist and the ticket goes back to open inventory.
