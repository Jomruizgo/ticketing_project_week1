The opportunity assignment feature spans the CRUD Service (crud_service/) for persistence and domain logic, and consumes events from RabbitMQ. Architecture is hexagonal: Domain, Application, Infrastructure, Api. Use .NET 8 with EF Core for PostgreSQL. Create a WaitlistOpportunity entity in Domain with fields: Id, WaitlistEntryId, TicketId, Status (pending/active/consumed/expired/failed), ActivatedAt, ExpiresAt. Define the OpportunityStatus enum with allowed transitions: Pending→Active, Pending→Failed, Active→Consumed, Active→Expired. Implement an IPrioritizationStrategy port in Domain/Interfaces with a FifoStrategy adapter in Infrastructure that queries the earliest active enrollment for the event. Create an AssignOpportunityCommand and AssignOpportunityHandler implementing IAssignOpportunityUseCase in Application/UseCases. The handler: (1) queries IPrioritizationStrategy for the next eligible buyer, (2) if none, returns "no eligible" so the ticket returns to inventory, (3) if found, creates WaitlistOpportunity with status Pending (persisted immediately for traceability), (4) calls ITicketReservationPort to reserve the ticket temporarily, (5) if reservation fails, transitions the opportunity to Failed via TransitionTo (Pending→Failed), logs the incident, and returns — the enrollment stays active for the next attempt, (6) if reservation succeeds, transitions the opportunity to Active via TransitionTo (Pending→Active), sets expiresAt = now + TTL, marks the enrollment as inactive, publishes the DLX message to q.waitlist.opportunity.delay (TTL starts from activation, not from creation), and notifies via IOpportunityObserver (Observer pattern). Define IOpportunityObserver port in Domain/Interfaces. Create a TicketReleasedConsumer in Infrastructure/Messaging that listens to the ticket.released routing key and invokes the use case. The consumer ACKs on success or business failure, NACKs with requeue:false on technical failure. The opportunity is published to RabbitMQ DLX queue for expiration: q.waitlist.opportunity.delay with TTL, dead-lettered to q.waitlist.opportunity.expired. Database table waitlist_opportunities uses snake_case columns. TDD: test handler with eligible buyer + successful reservation, eligible buyer + failed reservation, no eligible buyer. Use Testcontainers for integration tests verifying the FIFO query and unique constraint.
